Algèbre linéaire

Objectif: penser en vecteurs et matrices. C'est LA langue maternelle du ML: un modèle n'est qu'une suite de multiplications de matrices. Niveau le plus rentable de tout le parcours.

10 concepts
v⃗

Le vecteur

Une liste ordonnée de nombres = un point ou une flèche dans un espace à n dimensions. C'est l'unité de base: toute donnée devient un vecteur avant d'entrer dans un modèle.

▾
La formule
$$v = [v_1, v_2, \dots, v_n] \in \mathbb{R}^n$$
🤖 En machine learning

Un mot devient un vecteur (embedding), une image devient un vecteur de pixels, ton profil client devient un vecteur de features. « Vectoriser » = traduire le monde en nombres.

🛠 Comment t'en servir

np.array([1.2, 0.5, -3]). Intuition à cultiver: des vecteurs proches dans l'espace = des choses similaires dans le monde réel. Tout le ML repose sur cette idée.

💻 En code
v1 = torch.tensor([1, 2, 3])   # shape (3,)
v2 = torch.tensor([[1, 2, 3]])  # shape (1, 3)
# les deux ne sont PAS equivalents!
print(v1 @ v2.T)  # scalaire
print(v1 @ v2)     # erreur de shape
⚠️ Le piège

Attention au reshape: torch.tensor([1, 2, 3]).shape donne (3,) alors que torch.tensor([[1, 2, 3]]).shape donne (1, 3). Le premier est un VECTEUR (1D), le second est une MATRICE LIGNE (2D). Les operations comme @ et * ne se comportent pas pareil entre les deux.

u·v

Le produit scalaire

Multiplier deux vecteurs élément par élément et tout additionner: un seul nombre qui mesure à quel point ils pointent dans la même direction. Grand = alignés, 0 = perpendiculaires, négatif = opposés.

▾
La formule
$$u \cdot v = \sum_i u_i v_i = \|u\|\|v\|\cos\theta$$
🤖 En machine learning

C'est LE calcul de similarité: la recherche sémantique, les recommandations, et surtout l'attention des transformers (Q·K = « ce token est-il pertinent pour moi ? »).

🛠 Comment t'en servir

np.dot(u,v). Manipule le Lab 02: quand tu auras senti physiquement que produit scalaire = alignement, l'attention (niveau 8) deviendra évidente.

💻 En code
# produit scalaire = alignement:
u = F.normalize(emb_cat, dim=-1)   # embedding du mot 'chat'
v = F.normalize(emb_dog, dim=-1)   # embedding du mot 'chien'
similarite = (u @ v.T).item()       # proche de 1 = meme sens
⚠️ Le piège

Le produit scalaire ne capte que l'alignement LINEAIRE. u·v = 0 ne signifie pas 'pas de relation' mais 'perpendiculaire dans cet espace'. Deux mots peuvent etre relies (synonymes) sans alignement lineaire.

‖·‖₂

Normes L1 et L2

La norme mesure la longueur d'un vecteur. L2 = distance à vol d'oiseau (racine de la somme des carrés). L1 = distance « en taxi » (somme des valeurs absolues).

▾
La formule
$$\|v\|_2=\sqrt{\textstyle\sum v_i^2} \qquad \|v\|_1=\textstyle\sum |v_i|$$
🤖 En machine learning

Régularisation L2 (weight decay) = garder les poids petits. L1 = pousser des poids exactement à 0 (sélection de features). Gradient clipping = plafonner ‖∇L‖.

🛠 Comment t'en servir

Normaliser un vecteur (v / np.linalg.norm(v)) le ramène à longueur 1: indispensable avant une similarité cosinus, standard pour les embeddings.

💻 En code
# gradient clipping: on limite la norme du gradient
grad_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# si ||grad|| > 1, on le reduit a 1 sans changer la direction
⚠️ Le piège

L1 et L2 sont deux philosophies: L2 penalise les grands ecarts de maniere quadratique (les outliers ecrasent tout), L1 penalise lineairement (robuste mais non derivable en zero). Le choix = quel comportement face aux extremes.

W

La matrice

Un tableau de nombres (lignes × colonnes). Mais surtout: une matrice EST une transformation qui prend un vecteur et le projette dans un autre espace (rotation, étirement, changement de dimension).

▾
La formule
$$W \in \mathbb{R}^{m \times n}: \ \mathbb{R}^n \rightarrow \mathbb{R}^m$$
🤖 En machine learning

Chaque couche d'un réseau est une matrice de poids W. GPT-4, c'est essentiellement quelques milliers de matrices. « Paramètres du modèle » = les cases de ces matrices.

🛠 Comment t'en servir

Arrête de voir un tableau Excel: vois une machine à transformer des vecteurs. W de shape (768, 3072) = machine qui mange du 768 dimensions et crache du 3072.

💻 En code
# les deux ecritures sont equivalentes:
W = nn.Linear(768, 3072)          # PyTorch: (in, out)
# W stockee en [3072, 768] en interne
# W(x) = x @ W.T  (contrairement a la notation papier)
⚠️ Le piège

nn.Linear(in, out) stocke la matrice en (out, in) dans .weight. Si tu lis un papier qui ecrit W ∈ R^{in×out} et que tu codes nn.Linear(in, out), la multiplication est deja transposee: tu n'as rien a faire.

Wx

Le produit matriciel

Multiplier matrice × vecteur = calculer plein de produits scalaires d'un coup: chaque ligne de W fait son produit scalaire avec x. Règle des shapes: (m,n)×(n,p) → (m,p), les dimensions intérieures doivent coïncider.

▾
La formule
$$(AB)_{ij} = \sum_k A_{ik}B_{kj}$$
🤖 En machine learning

90% du calcul d'un LLM = des produits matriciels. C'est pour ça que les GPU existent en IA: ils font des milliards de multiplications-additions en parallèle.

🛠 Comment t'en servir

W @ x en NumPy/PyTorch. Le bug n°1 du débutant est une erreur de shape: prends l'habitude d'annoter chaque tenseur avec sa shape en commentaire.

💻 En code
# la regle des shapes:
A = torch.randn(32, 768)   # batch de 32, features 768
B = torch.randn(768, 3072) # matrice de poids
C = A @ B                   # (32, 768) @ (768, 3072) -> (32, 3072) ✓
# les 768 interieurs coincident
⚠️ Le piège

(m, n) @ (n, p) = (m, p): la dimension interieure n DISPARAIT. C'est la seule regle a retenir. Si tu lis 'la regle de la chaine en dimension n', c'est un produit de Jacobiennes qui suit exactement cette regle.

Aᵀ

La transposée

Aᵀ = retourner la matrice le long de sa diagonale: les lignes deviennent des colonnes. Sert surtout à faire coïncider les shapes pour les produits.

▾
La formule
$$(A^\top)_{ij} = A_{ji} \qquad (AB)^\top = B^\top A^\top$$
🤖 En machine learning

Dans l'attention: QKᵀ, on transpose K pour que chaque requête puisse faire son produit scalaire avec chaque clé. En backprop, les gradients traversent les couches via Wᵀ.

🛠 Comment t'en servir

A.T. Quand une multiplication plante pour cause de shapes, la transposée est souvent la clé, mais comprends POURQUOI avant de l'appliquer au hasard.

💻 En code
# transposer pour aligner les shapes:
x = torch.randn(32, 10)    # batch
W = torch.randn(5, 10)     # poids
z = x @ W.T                # (32, 10) @ (10, 5) = (32, 5) ✓
# sans T: (32, 10) @ (5, 10) -> erreur
⚠️ Le piège

(AB)^T = B^T A^T. L'ordre s'inverse quand tu transposes un produit. Si tu retiens une seule identite matricielle, retiens celle-la: elle te sauve 90% des erreurs de shape.

A⁻¹

Identité et inverse

I = la matrice « ne rien faire » (des 1 sur la diagonale). A⁻¹ = la transformation qui annule A: A⁻¹A = I. N'existe pas toujours.

▾
La formule
$$A^{-1}A = I \qquad Ax=b \Rightarrow x=A^{-1}b$$
🤖 En machine learning

La régression linéaire a une solution exacte via l'inverse (équation normale). En pratique sur de gros systèmes, inverser est trop coûteux et instable: on préfère la descente de gradient.

🛠 Comment t'en servir

np.linalg.solve(A,b) plutôt que inv(A) @ b (plus stable). Retiens surtout le concept: inverse = défaire une transformation.

💻 En code
# resoudre Ax = b SANS inverser:
A = torch.randn(100, 100)
b = torch.randn(100)
x = torch.linalg.solve(A, b)  # O(n^3) mais stable
# vs x = A.inverse() @ b      # moins stable, eviter
⚠️ Le piège

L'inverse d'une matrice n'existe pas toujours. Si le determinant est nul ou proche de zero, la matrice est 'singuliere': l'information a ete ecrasee et ne peut pas etre recuperee. En ML c'est frequent (rang faible).

λv

Valeurs et vecteurs propres

Les vecteurs propres d'une matrice sont ses directions privilégiées: A les étire (par un facteur λ, la valeur propre) sans les faire tourner. Ils révèlent la structure cachée de la transformation.

▾
La formule
$$Av = \lambda v$$
🤖 En machine learning

PCA trouve les directions de plus grande variance des données = vecteurs propres de la covariance. Le PageRank de Google est un vecteur propre. La stabilité d'un entraînement dépend des valeurs propres de la Hessienne.

🛠 Comment t'en servir

np.linalg.eig(A). Intuition suffisante pour 95% des usages: valeurs propres = « forces » de la matrice dans ses directions naturelles.

💻 En code
# PCA = vecteurs propres de la covariance:
X_centered = X - X.mean(dim=0)
cov = X_centered.T @ X_centered / (n-1)
eigvals, eigvecs = torch.linalg.eigh(cov)  # plus rapide que eig
# eigvals[0] = variance expliquee par le 1er axe
⚠️ Le piège

Les valeurs propres de la Hessienne (derivees secondes) determinent la vitesse de convergence de la descente de gradient. Un rapport grande/petite valeur propre eleve = 'ravin' = l'optimisation va zigzaguer.

UΣVᵀ

SVD : décomposition en valeurs singulières

Toute matrice se décompose en rotation × étirement × rotation. Les valeurs singulières classent l'information de la plus importante à la plus négligeable: on peut tronquer pour compresser.

▾
La formule
$$A = U\Sigma V^\top \approx U_r \Sigma_r V_r^\top$$
🤖 En machine learning

LoRA fine-tune les LLM en n'apprenant que des matrices de rang faible (l'idée même de la SVD tronquée). Compression de modèles, systèmes de recommandation, débruitage.

🛠 Comment t'en servir

np.linalg.svd(A). Garde les r plus grandes valeurs singulières = garder l'essentiel de A avec une fraction de la mémoire. C'est l'outil roi de la basse dimension.

💻 En code
U, S, Vt = torch.linalg.svd(A, full_matrices=False)
# reconstruction au rang r:
A_r = U[:, :r] @ torch.diag(S[:r]) @ Vt[:r, :]
# rapport S[0]/S[-1] = condition number = stabilite
⚠️ Le piège

Les valeurs singulieres decroissent GENERALEMENT vite. Les premieres contiennent l'essentiel de l'information, les dernieres sont du bruit. 'Couper a r' = garder le signal, jeter le bruit. C'est le principe du debruitage par SVD.

⧉

Le tenseur

Généralisation: scalaire (0D) → vecteur (1D) → matrice (2D) → tenseur (3D et plus). Juste un tableau multidimensionnel avec une shape.

▾
La formule
$$X \in \mathbb{R}^{B \times T \times d}$$
🤖 En machine learning

Le tenseur standard d'un LLM: (batch, tokens, dimension) = par exemple (32, 2048, 768). Une image en batch: (B, canaux, hauteur, largeur). D'où le nom TensorFlow.

🛠 Comment t'en servir

En PyTorch tout est torch.Tensor. Compétence clé: lire et manipuler les shapes (.shape, .reshape, .permute). Maîtrise ça et le code des repos de recherche s'ouvre à toi.

💻 En code
# les 3 axes d'un tenseur transformer:
x = torch.randn(4, 128, 768)  # (batch=4, tokens=128, dim=768)
# les operations selon chaque axe:
x.mean(dim=0)  # moyenne sur le batch: [128, 768]
x.mean(dim=1)  # moyenne par token: [4, 768]
x.mean(dim=2)  # moyenne des features: [4, 128]
⚠️ Le piège

Tenseur = matrice avec plus de 2 axes. Chaque axe a un sens (batch, sequence, feature). Un reshape maladroit melange les dimensions et detruit la semantique. Toujours commenter la signification de chaque axe.
