Lire les mathématiques

Objectif: décoder n'importe quelle équation comme une phrase. Les maths sont une langue: ici tu apprends l'alphabet et la grammaire. Après ce niveau, plus aucun symbole d'un papier ML ne te bloque.

13 concepts
αβθ

Les lettres grecques

Pas de panique: ce sont juste des noms de variables, comme x ou lr en code. Chaque lettre a un rôle habituel qu'on retrouve partout.

▾
La formule
$$\alpha,\ \beta,\ \theta,\ \lambda,\ \mu,\ \sigma,\ \varepsilon,\ \eta$$
🤖 En machine learning

θ = les paramètres du modèle (poids). α ou η = learning rate. λ = force de régularisation. μ = moyenne. σ = écart-type. ε = un tout petit nombre (éviter division par zéro).

🛠 Comment t'en servir

Quand tu lis une équation, remplace mentalement chaque lettre grecque par son nom de variable code: θ devient weights, α devient lr. L'équation devient du pseudo-code.

💻 En code
alpha = 0.001  # learning rate
theta = model.state_dict()  # les poids du modele
⚠️ Le piège

Les lettres grecques ne sont pas magiques: ce sont juste des noms de variable. theta et alpha sont les plus frequentes, les autres apparaissent dans un papier precis -> note leur definition.

xᵢ

Indices et exposants

x_i = le i-ème élément d'une liste (comme x[i]). x² = puissance. Piège: x^{(j)} avec parenthèses = le j-ème exemple du dataset, pas une puissance.

▾
La formule
$$x_i = x[i] \qquad x^{(j)} = \text{exemple } j$$
🤖 En machine learning

Dans les papiers: x⁽ⁱ⁾ est la i-ème donnée d'entraînement, xⱼ la j-ème feature, Wᵢⱼ la cellule ligne i colonne j d'une matrice de poids.

🛠 Comment t'en servir

Lis toujours les indices comme des accès tableau: W_{ij} = W[i][j]. Une équation avec indices est une boucle for déguisée.

💻 En code
batch[:, 0]      # x_i: tous les exemples, feature 0
batch[0, :]      # x^(j): le premier exemple du batch
⚠️ Le piège

Les indices papier commencent a 1 mais Python a 0. Quand tu lis W_{ij} dans un papier, ecris W[i][j] en code avec le decalage mental.

Σ

Sigma : la somme

Σ signifie simplement une boucle for qui additionne. En dessous: où commence la boucle. Au dessus: où elle finit. À droite: ce qu'on additionne à chaque tour.

▾
La formule
$$\sum_{i=1}^{n} x_i = x_1 + x_2 + \dots + x_n$$
🤖 En machine learning

La loss totale d'un modèle est presque toujours une somme des erreurs sur chaque exemple: L = Σ des erreurs individuelles, souvent divisée par n (moyenne).

🛠 Comment t'en servir

Traduction directe en Python: sum(x[i] for i in range(n)). Dès que tu vois Σ, écris la boucle dans ta tête et le symbole perd tout son mystère.

💻 En code
loss = F.mse_loss(pred, target, reduction='sum')  # Sigma des erreurs
loss = F.mse_loss(pred, target, reduction='mean')      # (1/n) Sigma, standard
⚠️ Le piège

Sigma seule grossit avec n. En pratique on utilise (1/n)Sigma (mean) pour que la loss soit comparable entre batches de tailles differentes.

Π

Pi majuscule : le produit

Le frère de Σ mais qui multiplie au lieu d'additionner. Une boucle for avec *=.

▾
La formule
$$\prod_{i=1}^{n} p_i = p_1 \times p_2 \times \dots \times p_n$$
🤖 En machine learning

La vraisemblance d'un dataset = produit des probabilités de chaque exemple. Comme multiplier plein de petits nombres tend vers 0, on passe au log qui transforme Π en Σ.

🛠 Comment t'en servir

math.prod(p) en Python. Retiens le réflexe clé du ML: log(Π) = Σ log. C'est pour ça que toutes les loss sont des log-quelque-chose.

💻 En code
log_likelihood = sum(log(prob) for prob in probs)  # log(Pi) = Sigma(log)
# sous le capot: c'est ce que fait cross_entropy
⚠️ Le piège

Le produit direct de 1000 probabilites < 1 donne un nombre tellement petit que l'ordinateur le tronque a 0. Le log transforme ce cancer numerique en somme stable.

∈ ℝ

Ensembles : ∈, ℝ, ℝⁿ

∈ = « appartient à » (est de type). ℝ = les nombres réels (un float). ℝⁿ = un vecteur de n floats. ℝ^{m×n} = une matrice m lignes n colonnes.

▾
La formule
$$x \in \mathbb{R}^{768} \quad W \in \mathbb{R}^{768\times 3072}$$
🤖 En machine learning

« x ∈ ℝ⁷⁶⁸ » = un embedding de dimension 768. « W ∈ ℝ⁷⁶⁸ˣ³⁰⁷² » = la matrice de poids d'une couche. C'est la déclaration de type des maths.

🛠 Comment t'en servir

Lis ∈ comme une annotation de type: x: Tensor[768]. Quand tu lis un papier, note d'abord les « shapes » déclarées avec ∈, ça t'évite 90% de la confusion.

💻 En code
def forward(self, x: Tensor[Batch, 784]) -> Tensor[Batch, 10]:
    return self.W @ x + self.b
# les types sont la signature de la fonction
⚠️ Le piège

Les declarations de type avec ∈ ne sont pas du decor. Si un papier dit W ∈ R^{768x3072} et que ta matrice est [3072, 768], tout est faux sans erreur explicite.

∀∃

Quantificateurs : ∀ et ∃

∀ = « pour tout » (chaque élément sans exception). ∃ = « il existe » (au moins un).

▾
La formule
$$\forall x \in D,\ f(x) \ge 0$$
🤖 En machine learning

« ∀x, loss(x) ≥ 0 » = la loss est positive pour tous les exemples. Utilisé dans les preuves, définitions et garanties théoriques (convergence, bornes).

🛠 Comment t'en servir

∀ = all(...), ∃ = any(...). Ces symboles apparaissent surtout dans les sections théoriques des papiers, tu peux souvent les survoler en première lecture.

💻 En code
assert all(loss >= -1e-6 for loss in losses)  # ∀ loss >= 0
# faux si une loss est negative -> bug
⚠️ Le piège

∀ et ∃ sont la matiere des preuves et des garanties. Dans un papier, ∀ signifie 'vrai pour tous les cas, sans exception'. Un seul contre-exemple suffit a le tuer.

‖x‖

|x| et ‖x‖ : tailles

|x| = valeur absolue d'un nombre (distance à zéro). ‖x‖ = norme d'un vecteur: sa longueur. Deux barres = version vecteur d'une barre.

▾
La formule
$$\|x\|_2 = \sqrt{x_1^2 + x_2^2 + \dots + x_n^2}$$
🤖 En machine learning

La norme mesure la « taille » d'un gradient (gradient clipping), d'un vecteur de poids (weight decay), ou la distance entre deux embeddings.

🛠 Comment t'en servir

np.linalg.norm(x). Quand tu vois ‖·‖² dans une loss, c'est presque toujours « erreur au carré » ou « pénalité sur la taille des poids ».

💻 En code
v = torch.tensor([3.0, 4.0])
norme = torch.norm(v)  # ||v|| = sqrt(3^2 + 4^2) = 5.0
# en numpy: np.linalg.norm(v)

# normaliser un vecteur (le ramener a longueur 1):
norme = v / torch.norm(v)  # [0.6, 0.8]
⚠️ Le piège

||x|| en exposant (||x||^2) apparait dans les loss MSE et weight decay. Ne confonds pas |x| (valeur absolue, un nombre) et ||x|| (norme, longueur d'un vecteur). C'est deux concepts differents.

arg

argmax et argmin

max(f) = la valeur maximale. argmax(f) = l'endroit (l'argument) où ce maximum est atteint. Nuance capitale en ML.

▾
La formule
$$\hat{y} = \underset{c}{\operatorname{argmax}}\ p(c \mid x)$$
🤖 En machine learning

La prédiction finale d'un classifieur: la classe c qui a la plus grande probabilité. L'entraînement lui-même est un argmin: trouver les θ qui minimisent la loss.

🛠 Comment t'en servir

np.argmax(probs) te donne l'indice, np.max(probs) la valeur. Tout le ML tient en une ligne: θ* = argmin de la loss.

💻 En code
def predict(logits):
    return logits.argmax(dim=-1)  # renvoie l'INDICE de la meilleure classe
    # pas la valeur max, mais SA POSITION
⚠️ Le piège

argmax et max renvoient deux choses differentes: max donne la valeur, argmax donne la POSITION. Faire l'inverse sans s'en rendre compte est un classique.

E[X]

E[·] et P(·)

P(A) = probabilité de l'événement A (entre 0 et 1). E[X] = espérance: la moyenne pondérée attendue de X. P(A|B) = proba de A sachant que B est vrai.

▾
La formule
$$\mathbb{E}[X] = \sum_i x_i\, p_i$$
🤖 En machine learning

La loss qu'on optimise est en théorie une espérance sur toutes les données possibles; en pratique on l'estime par la moyenne sur le batch. E[·] partout dans les papiers = « en moyenne ».

🛠 Comment t'en servir

Chaque fois que tu vois E[...], lis « la moyenne de ... sur les données ». En code, c'est .mean() sur le batch. Ce réflexe débloque la moitié des équations de RL et de LLM.

💻 En code
x = torch.tensor([1.0, 2.0, 3.0])
p = torch.tensor([0.2, 0.3, 0.5])  # probabilites (somme = 1)
E = (x * p).sum()  # E[X] = 1*0.2 + 2*0.3 + 3*0.5 = 2.3

# equivalent a la moyenne si toutes les probas sont egales:
moyenne = x.mean()  # (1+2+3)/3 = 2.0
⚠️ Le piège

E[X] = 0 ne signifie PAS que la moyenne de tes 100 echantillons sera 0. Elle le SERAIT si tu en avais une infinite, mais avec n echantillons il y a un ecart residuel. L'esperance est la valeur theorique, la moyenne empirique est son approximation.

∂∇

∂ et ∇ (aperçu)

∂ = dérivée partielle: « de combien bouge la sortie si je bouge UNE variable ». ∇ (nabla) = gradient: toutes les dérivées partielles rangées dans un vecteur. Détaillés au niveau 3.

▾
La formule
$$\nabla_\theta L = \left[\tfrac{\partial L}{\partial \theta_1}, \dots, \tfrac{\partial L}{\partial \theta_n}\right]$$
🤖 En machine learning

∇L (le gradient de la loss) est LE signal d'apprentissage: il dit à chaque poids dans quel sens bouger pour réduire l'erreur.

🛠 Comment t'en servir

Pour l'instant retiens juste la lecture: « ∇θ L » se lit « gradient de la loss par rapport aux paramètres ». En PyTorch: loss.backward() le calcule pour toi.

💻 En code
x = torch.tensor(3.0, requires_grad=True)  # feuille du graphe
y = x ** 2
y.backward()  # remonte le gradient jusqu'a x
print(x.grad)  # 6.0, soit dy/dx en x=3
⚠️ Le piège

∂ et ∇ sont les memes objets a deux echelles: ∂ pour une composante, ∇ pour le vecteur complet. ∇L est trop gros pour etre affiche mais ∂L/∂w_i se lit dans w_i.grad.

ŷ x̄

Chapeau, barre, tilde, étoile

ŷ (chapeau) = valeur prédite/estimée. x̄ (barre) = moyenne. x̃ (tilde) = version bruitée ou approchée. θ* (étoile) = la valeur optimale.

▾
La formule
$$\hat{y} \approx y \qquad \bar{x} = \tfrac{1}{n}\sum_i x_i$$
🤖 En machine learning

Toute la littérature ML: ŷ = sortie du modèle, y = vraie étiquette, la loss compare les deux. θ* = les poids parfaits qu'on cherche à approcher.

🛠 Comment t'en servir

Réflexe de lecture: chapeau = « estimé par le modèle », étoile = « le meilleur possible ». Ces décorations changent le sens d'un symbole sans changer la lettre.

💻 En code
y_hat = model(x)     # prediction: chapeau = estime par le modele
y = labels            # verite terrain: sans chapeau = reel
loss = (y_hat - y).pow(2).mean()  # MSE: compare les deux
⚠️ Le piège

La convention chapeau/barre/tilde/etoile n'est jamais expliquee dans les papiers, elle est sous-entendue. Si tu vois un symbole decore que tu ne reconnais pas, cherche sa definition a la premiere occurrence.

f:→

Signatures : f: ℝⁿ → ℝ

La flèche déclare ce qui entre et ce qui sort d'une fonction. « f: ℝⁿ → ℝ » = f prend un vecteur de n nombres et rend un seul nombre.

▾
La formule
$$f: \mathbb{R}^{n} \rightarrow \mathbb{R}^{m}$$
🤖 En machine learning

Un réseau de neurones entier se déclare ainsi: GPT est une fonction ℝ^{contexte} → ℝ^{vocabulaire}. Une loss est toujours → ℝ (elle sort UN nombre à minimiser).

🛠 Comment t'en servir

C'est la signature de fonction des maths, exactement comme def f(x: Vec[n]) -> float. Identifier les shapes d'entrée/sortie est ta première étape face à toute équation.

💻 En code
# signature d'un classifieur:
# f: R^784 -> [0,1]^10  (softmax en sortie)
# la signature dit tout: 784 pixels en entree, 10 probas en sortie
⚠️ Le piège

La signature f: A -> B est la premiere chose a lire dans un papier. Avant de comprendre COMMENT ca marche, comprends CE QUE ca mange et CE QUE ca rend.

∝≈

Comparer : ∝, ≈, ≫, ⇒

≈ = environ égal. ∝ = proportionnel à (égal à un facteur constant près). ≫ = très supérieur. ⇒ = implique.

▾
La formule
$$P(\theta\mid D) \propto P(D\mid\theta)\,P(\theta)$$
🤖 En machine learning

Bayes s'écrit souvent avec ∝ pour ignorer la constante de normalisation. Les scaling laws utilisent ∝: la loss ∝ (taille du modèle)^{-α}.

🛠 Comment t'en servir

∝ te dit « la forme compte, pas l'échelle ». Quand un papier écrit ∝, il te dispense de calculer un dénominateur pénible: profite-en.

💻 En code
# proportionnel: double les donnees -> double la perte
# approx: 3.14159 ≈ 3.14
# implique: si le modele converge, alors loss diminue
⚠️ Le piège

∝ (proportionnel) et ≈ (approximativement) ne sont pas des symboles de paresse: ils signalent qu'on a deliberately ignore un facteur constant ou un terme negligeable. C'est un choix, pas une imprecision.
