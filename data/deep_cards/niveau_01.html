f(x)

La fonction

Une fonction est une machine: tu mets x dedans, elle sort f(x). Rien de plus. Tout modèle ML est une fonction, juste très grosse.

▾
La formule
$$f(x) = \text{sortie quand l'entrée vaut } x$$
🤖 En machine learning

GPT est une fonction: entrée = ton texte, sortie = probabilités du mot suivant. Un détecteur de spam: entrée = email, sortie = un score. « Modèle » = « fonction avec des réglages ».

🛠 Comment t'en servir

Habitue-toi à voir f(x) comme def f(x): return .... Question réflexe devant toute fonction: quel est le type de l'entrée, le type de la sortie ? Utilise le Lab 01 ci-dessous.

💻 En code
def modele(x):
    return self.couche3(self.couche2(self.couche1(x)))
# f est la fonction, f(x) est sa valeur en x
# le modele = f, l'inference = f(x)
⚠️ Le piège

Ne dis jamais 'la fonction f(x)' car f(x) est la valeur, pas la fonction. f est la fonction, f(x) est le resultat de son application a x. Cette distinction evite des confusions en backprop.

ax+b

La droite ax + b

La fonction la plus importante du ML: a contrôle la pente (l'inclinaison), b décale vers le haut ou le bas. C'est déjà... un neurone.

▾
La formule
$$f(x) = ax + b$$
🤖 En machine learning

Un neurone calcule exactement w·x + b: une somme pondérée plus un biais. La régression linéaire, c'est trouver le meilleur a et b. Le deep learning empile des millions de ax+b.

🛠 Comment t'en servir

Joue avec a et b dans le Lab 01 jusqu'à ce que leur effet soit instinctif. Quand tu entends « poids » pense a, quand tu entends « biais » pense b.

💻 En code
pente = (y2 - y1) / (x2 - x1)  # a, le coefficient directeur
biais = y1 - pente * x1           # b, l'ordonnee a l'origine
# en ML: w = pente, b = biais
⚠️ Le piège

a = 0 → droite horizontale (la sortie ne depend pas de l'entree). a < 0 → pente negative. a ≫ 1 → tres sensible. a = 0 est un cas interessant: la feature est ignoree.

xⁿ

Puissances et polynômes

x² = x·x, x³ = x·x·x. Un polynôme = somme de puissances. Plus le degré est haut, plus la courbe peut onduler et épouser des formes complexes.

▾
La formule
$$f(x)=3x^2 - 2x + 1$$
🤖 En machine learning

x² apparaît dans la loss MSE (erreur au carré: punit fort les grosses erreurs, oublie le signe). Les polynômes de haut degré illustrent l'overfitting: trop flexibles, ils mémorisent le bruit.

🛠 Comment t'en servir

Retiens: mettre au carré = rendre positif + amplifier les gros écarts. C'est pour ça que « moindres carrés » est partout depuis 200 ans.

💻 En code
loss = F.mse_loss(pred, target)  # (pred - target)^2
# c'est un polynome de degre 2: x^2
# pourquoi x^2? parce que derivable et convexe
⚠️ Le piège

Plus le degre d'un polynome est eleve, plus la courbe peut onduler. Un polynome de degre 100 sur 10 points passe exactement par chaque point mais devient fou entre eux: c'est l'overfitting en une image.

eˣ

L'exponentielle

e ≈ 2.718. e^x explose quand x grandit, et écrase vers 0 (sans jamais l'atteindre) quand x est négatif. Toujours strictement positive.

▾
La formule
$$e^x > 0 \quad \forall x \qquad e^{a+b}=e^a e^b$$
🤖 En machine learning

Softmax utilise e^x pour transformer n'importe quels scores en nombres positifs avant de les normaliser en probabilités. La sigmoïde aussi. La décroissance du learning rate est souvent exponentielle.

🛠 Comment t'en servir

np.exp(x). Propriété d'or: l'expo transforme les additions en multiplications. Sa réciproque (le log) fait l'inverse: le duo exp/log est le moteur de toutes les probas en ML.

💻 En code
# pourquoi softmax utilise exp:
# exp transforme [-inf, +inf] en [0, +inf]
# puis la normalisation donne [0, 1]
z = torch.tensor([-2., 0., 3.])
print(torch.exp(z))  # [0.135, 1.0, 20.09]
⚠️ Le piège

exp ne tombe JAMAIS a zero. meme pour x = -1000, exp(-1000) ≈ 10^{-434} > 0 strictement. C'est pour ca que softmax ne donne jamais de probabilite exactement nulle.

log

Le logarithme

log répond à la question: « e puissance combien donne ce nombre ? ». Il compresse les grands nombres et transforme les produits en sommes. log(1)=0, log(x<1) est négatif.

▾
La formule
$$\log(ab) = \log a + \log b \qquad \log e^x = x$$
🤖 En machine learning

Les loss s'appellent log-loss car on maximise log(vraisemblance) au lieu de la vraisemblance: le produit de 10000 probas devient une somme de 10000 logs, numériquement stable.

🛠 Comment t'en servir

Réflexe: proba proche de 1 → log proche de 0 (bonne prédiction, faible loss). Proba proche de 0 → log très négatif (loss énorme). C'est exactement la cross-entropy que tu verras au niveau 4.

💻 En code
# passage en log d'une probabilite:
p = torch.tensor([0.01, 0.5, 0.99])
print(torch.log(p))  # [-4.61, -0.69, -0.01]
# les petites probabilites deviennent de grands negatifs
⚠️ Le piège

log n'est defini QUE pour x > 0. log(0) = -inf. Si ta loss contient un log(prediction), assure-toi que la prediction est strictement positive en la softmaxant ou en ajoutant un epsilon.

f∘g

Composition de fonctions

f(g(x)) = brancher la sortie de g dans l'entrée de f: un pipeline. L'ordre compte: on applique g d'abord.

▾
La formule
$$(f \circ g)(x) = f(g(x))$$
🤖 En machine learning

Un réseau profond EST une composition: couche3(couche2(couche1(x))). « Profond » signifie littéralement « beaucoup de fonctions composées ». Backprop dérive cette composition.

🛠 Comment t'en servir

Pense pipeline Unix: x | g | f. Quand tu vois une tour d'équations imbriquées dans un papier, dessine le pipeline de gauche à droite, tout devient limpide.

💻 En code
# composee de 3 couches:
def forward(self, x):
    h1 = F.relu(self.fc1(x))    # g1
    h2 = F.relu(self.fc2(h1))   # g2 compose g1
    out = self.fc3(h2)           # g3 compose g2 compose g1
    return out
⚠️ Le piège

La composee f∘g signifie g d'abord, f ensuite. Lis de droite a gauche: x → g → f. L'erreur classique est de lire dans l'ordre d'ecriture et d'inverser le pipeline.

x=?

Équations et résolution

Résoudre f(x)=0, c'est chercher quelle entrée produit la sortie voulue. Souvent impossible à la main pour les grosses fonctions: on cherche alors une solution approchée, par itérations.

▾
La formule
$$\text{trouver } \theta \text{ tel que } \nabla L(\theta)=0$$
🤖 En machine learning

Entraîner un modèle = résoudre ∇L(θ)=0 (pente nulle = fond de la vallée). Comme il y a des milliards de θ, on ne résout pas: on descend pas à pas (niveau 5).

🛠 Comment t'en servir

Change de mentalité: en ML on ne « résout » presque jamais exactement, on approxime itérativement. Accepter ça, c'est comprendre pourquoi l'entraînement prend des heures de GPU.

💻 En code
# on ne resout pas ∇L = 0, on marche vers la solution:
for _ in range(1000):
    loss = model(x, y)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
# approximer iterativement, la cle du ML
⚠️ Le piège

En ML on ne resout JAMAIS les equations. On fait des pas successifs vers une solution qu'on n'atteindra jamais exactement. La question n'est pas 'est-ce que la solution est exacte?' mais 'est-ce qu'elle est assez bonne?'
