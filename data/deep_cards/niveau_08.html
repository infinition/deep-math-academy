tok

La tokenisation

Découper le texte en tokens: des morceaux de mots issus d'un vocabulaire appris par fréquence (BPE). « anticonstitutionnellement » → plusieurs tokens; « the » → un seul. Le modèle ne voit que des numéros de tokens.

▾
La formule
$$\text{texte} \rightarrow [t_1, t_2, \dots, t_n], \ t_i \in \{1..V\}$$
🤖 En machine learning

Explique les comportements étranges des LLM: difficultés à compter les lettres, à faire de l'arithmétique sur grands nombres, coûts facturés au token, langues non anglaises plus coûteuses (plus de tokens par mot).

🛠 Comment t'en servir

Joue avec un tokenizer en ligne (tiktoken) sur tes propres textes: voir le découpage réel dissipe la moitié des mystères des LLM. ~0.75 mot par token en anglais, moins en français.

💻 En code
# voir le tokenizer en action:
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained('bert-base-uncased')
print(tok.tokenize('anticonstitutionnellement'))
# ['anti', '##const', '##itu', '##tion', '##nelle', '##ment']
# le modele ne voit PAS les lettres a, n, t, i...
# il voit des morceaux de mots appris par frequence
print(tok.encode('Hello world'))  # [101, 7592, 2088, 102] (IDs)
⚠️ Le piège

Les LLM ne connaissent PAS l'alphabet. Quand tu demandes 'combien de r dans strawberry?', le modele voit ['st', 'raw', 'berry'] ou ['straw', 'berry'] selon le tokenizer. Il n'a jamais appris ce qu'est la lettre 'r'. D'ou la difficulte.

QKV

L'attention (Q, K, V)

Chaque token émet une requête (Q: ce que je cherche), une clé (K: ce que je propose) et une valeur (V: mon contenu). Produit scalaire Q·K = pertinence, softmax = pondération, moyenne pondérée des V = nouvelle représentation. Chaque token « regarde » les autres et absorbe ce qui l'aide.

▾
La formule
$$\text{Att}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$
🤖 En machine learning

LA formule de l'IA moderne: GPT, Claude, BERT, ViT, AlphaFold, Whisper. Le √d_k évite que les produits scalaires saturent le softmax. Coût quadratique en longueur: d'où la course aux contextes longs.

🛠 Comment t'en servir

Relis cette formule bloc par bloc avec tes acquis: produit scalaire (N2) = similarité, softmax (N6) = poids, moyenne pondérée (N4) = espérance. Tu possèdes déjà chaque pièce: c'est le boss final qui n'en est pas un.

💻 En code
# attention entre 3 tokens:
Q = torch.randn(3, 64)  # 3 tokens, chaque requete en 64d
K = torch.randn(3, 64)
V = torch.randn(3, 64)
scores = Q @ K.T / math.sqrt(64)  # (3,3): chaque token VS chaque token
poids = F.softmax(scores, dim=-1)  # normalisation par token
sortie = poids @ V                # melange pondere des valeurs
# le token 1 regarde les tokens 1,2,3 et absorbe ce qui est pertinent
⚠️ Le piège

L'attention calcule des poids DYNAMIQUES: ils dependent du contenu des tokens, pas de leur position fixe. C'est la difference fondamentale avec une convolution (poids fixes) ou un RNN (ordre impose). Le coût O(T^2) limite la longueur de contexte.

×h

L'attention multi-têtes

Faire tourner h attentions en parallèle, chacune avec ses propres projections Q,K,V dans un sous-espace: une tête suit la syntaxe, une autre les coréférences, une autre les positions... puis on concatène.

▾
La formule
$$\text{MHA} = \text{Concat}(\text{head}_1,\dots,\text{head}_h)W^O$$
🤖 En machine learning

Standard: 12 à 128 têtes selon la taille du modèle. L'interprétabilité mécaniste (Anthropic notamment) dissèque ces têtes et y découvre des circuits: têtes d'induction, de copie, de négation.

🛠 Comment t'en servir

Retiens l'intuition: plusieurs experts qui lisent la même phrase avec des lunettes différentes. En code, c'est un simple reshape (B, T, h, d/h) suivi d'attentions parallèles.

💻 En code
# attention multi-tetes decomposee:
d_model = 768
h = 12  # tetes
d_k = d_model // h  # 64
# chaque tete travaille dans un sous-espace de 64 dimensions
# requete pour toutes les tetes simultanement:
Q = linear_q(x).view(B, T, h, d_k).transpose(1, 2)
# Q.shape: [B, h, T, d_k]
# chaque tete a sa propre copie de Q,K,V
# les sorties sont concatenees et reprojetees
⚠️ Le piège

Chaque tete d'attention apprend un type de relation different: certaines suivent la syntaxe (sujet-verbe), d'autres les coreferences (il → chat), d'autres la position (token precedent). 12 tetes = 12 lenses differentes sur la meme phrase.

pos

L'encodage positionnel

L'attention est aveugle à l'ordre (permuter les tokens donne les mêmes scores): on injecte donc la position dans les représentations, via des sinusoïdes, des embeddings appris, ou des rotations (RoPE).

▾
La formule
$$PE_{(pos,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right)$$
🤖 En machine learning

Sans lui, « le chat mange la souris » = « la souris mange le chat ». RoPE (rotary) équipe Llama, Qwen et la plupart des LLM récents, et conditionne l'extrapolation à des contextes plus longs.

🛠 Comment t'en servir

À l'usage, sache simplement: c'est ce qui donne la notion d'ordre au modèle, et c'est un des leviers des contextes 1M tokens. Détail d'implémentation sauf si tu codes un transformer from scratch.

💻 En code
# RoPE: encoder la position dans des rotations
# sans entrer dans les details techniques:
# chaque paire de dimensions (2i, 2i+1) dans Q et K
# subit une rotation dont L'ANGLE depend de la position
# l'attention entre token i et token j depend alors de (j-i)
# c'est la position RELATIVE qui compte, pas l'absolue

# le resultat est qu'on peut "apprendre a etre 3 tokens plus loin"
# independamment de la position de depart (0, 100 ou 1000)
⚠️ Le piège

RoPE encode la position dans l'ANGLE de rotation des paires de dimensions. La difference de position entre token i et token j est encodee dans la DIFFERENCE d'angle. L'attention peut ainsi 'apprendre a etre 3 tokens plus loin' independamment de la position absolue.

LN+

Layer norm et résiduels

Deux astuces de plomberie qui rendent les réseaux TRÈS profonds entraînables. Résiduel: sortie = x + f(x), le gradient a une autoroute directe vers les premières couches. Layer norm: standardiser chaque token individuellement pour stabiliser.

▾
La formule
$$h' = \text{LN}(h + \text{Att}(h))$$
🤖 En machine learning

Le bloc transformer = [LN → attention → addition résiduelle → LN → MLP → addition résiduelle], répété 12 à 100+ fois. Sans résiduels, impossible d'entraîner au-delà de ~20 couches.

🛠 Comment t'en servir

Vision moderne éclairante: le « residual stream » est un bus de données que chaque couche lit et enrichit. Ce cadre (utilisé en interprétabilité) rend l'architecture entière limpide.

💻 En code
# le bloc transformer standard:
class TransformerBlock(nn.Module):
    def forward(self, x):
        # x passe dans le 'residual stream'
        resid = x
        x = self.ln1(x)
        x = self.attn(x)
        x = resid + x  # AJOUT: le gradient traverse directement
        resid = x
        x = self.ln2(x)
        x = self.mlp(x)
        x = resid + x  # AJOUT: deuxieme autoroute
        return x
# le 'x = x + f(x)' porte le nom de 'skip connection' ou 'residual connection'
⚠️ Le piège

SANS les connexions residuelles (le 'x + f(x)'), le gradient de la loss devait traverser 100 couches en se multipliant par les derivees de chaque couche → vanishing/exploding gradient. AVEC, le gradient a une autoroute directe: le '1' dans d(x + f(x))/dx = 1 + f'(x).

T°

Température et sampling

À l'inférence, on divise les logits par T avant le softmax. T faible (0.1): distribution piquée, sorties sûres et répétitives. T élevée (1.5): distribution plate, créatif mais incohérent. S'y ajoutent top-k et top-p (couper la queue).

▾
La formule
$$p_i = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}$$
🤖 En machine learning

Le réglage que tu utilises déjà dans chaque appel API: T≈0 pour du code ou de l'extraction, T≈0.7-1.0 pour de la rédaction créative. greedy = argmax = T→0.

🛠 Comment t'en servir

Manipule le Lab 04: vois la distribution se déformer en direct. Retiens que le modèle ne change pas: seule la façon de TIRER dans sa distribution change.

💻 En code
# l effet de la temperature sur le tirage:
logits = torch.tensor([2.0, 1.0, 0.5])
for T in [0.1, 1.0, 5.0]:
    probs = F.softmax(logits / T, dim=-1)
    print(f'T={T}: {probs}')
    # T=0.1: [0.99, 0.01, 0.00] → quasi deterministe
    # T=1.0: [0.73, 0.20, 0.07] → normal
    # T=5.0: [0.41, 0.33, 0.26] → presque uniforme
    # T faible = accentue les differences, T fort = les gomme
⚠️ Le piège

Temperature NE CHANGE PAS le modele, seulement la facon de tirer dans sa distribution. A T=0, c'est toujours le token le plus probable qui sort (argmax). A T=∞, tous les tokens sont equiprobables. L'editorial d'un journal utilise T bas, le slam poetry utilise T haut.

PT→FT

Pré-entraînement et fine-tuning

Pré-entraînement: apprendre le langage sur des trillions de tokens (prédire le mot suivant), des mois de GPU. Fine-tuning: spécialiser ce modèle généraliste sur TA tâche avec peu de données. Le transfer learning à l'échelle.

▾
La formule
$$\theta_{task} = \theta_{pretrained} + \Delta\theta$$
🤖 En machine learning

Le paradigme dominant: personne ne réentraîne from scratch. Variantes: SFT (instructions), RLHF/DPO (préférences humaines), continued pretraining (domaine spécialisé: juridique, médical, cyber).

🛠 Comment t'en servir

Arbre de décision pratique: prompt engineering d'abord (gratuit), puis RAG (connaissance externe), puis fine-tuning (style/format/domaine), dans cet ordre de coût croissant.

💻 En code
# fine-tuning: partir d un modele existant
from transformers import AutoModelForSequenceClassification
# charger les poids d un modele entraine sur des milliards de tokens
model = AutoModelForSequenceClassification.from_pretrained('bert-base-uncased')
# remplacer la tete de classification
model.classifier = nn.Linear(768, n_classes)
# entrainer avec un lr 100x plus petit
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)
⚠️ Le piège

Le pre-entrainement a deja integre la grammaire, la semantique, les faits generaux. Le fine-tuning n'a besoin que de DECALER legerement ces connaissances vers TA tache. Si tu utilises un lr de pre-entrainement (3e-4), les connaissances apprises sont detruites en quelques steps.

LoRA

LoRA

Fine-tuner un LLM sans toucher à ses milliards de poids: on gèle tout et on apprend seulement de petites matrices de rang faible (A×B) ajoutées en parallèle. 0.1% des paramètres, ~100% du résultat.

▾
La formule
$$W' = W_{frozen} + \underbrace{BA}_{\text{rang } r \ll d}$$
🤖 En machine learning

Rend le fine-tuning accessible sur un seul GPU grand public (QLoRA: sur du quantifié 4-bit). L'écosystème open source (Llama, Mistral, Qwen) repose massivement dessus. C'est la SVD (niveau 2) devenue industrie.

🛠 Comment t'en servir

Librairie peft de HuggingFace, r entre 8 et 64. Boucle complète: tu as l'algèbre linéaire du niveau 2 qui explique POURQUOI le rang faible suffit: les mises à jour utiles vivent dans un petit sous-espace.

💻 En code
# ajouter un adaptateur LoRA:
from peft import LoraConfig, get_peft_model
config = LoraConfig(
    r=8,                # rang: la correction est de rang 8
    lora_alpha=32,      # echelle de la mise a jour
    target_modules=['q_proj', 'v_proj']  # sur quelles couches
)
model = get_peft_model(model, config)
# parametres entrainables: 0.1% du modele original
# le reste est gele (pas de gradient, pas de mise a jour)
⚠️ Le piège

LoRA = correction de rang faible. L'hypothese: quand on fine-tune un LLM, les changements de poids (ΔW) vivent dans un espace de petite dimension. Avec r=8, chaque poids de 4096×4096 est modifie via deux petits blocs B (4096×8) et A (8×4096): 65k parametres au lieu de 16M. C'est exactement la SVD tronquee du niveau 2, mais apprise directement au lieu d'etre calculee.

Règle d'or : ne passe au niveau suivant que si tu peux expliquer chaque carte à voix haute, sans la relire.
