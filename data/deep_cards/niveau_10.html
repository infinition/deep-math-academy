Lire un papier efficacement

Jamais linéairement. 3 passes: (1) titre, abstract, figures, conclusion: 10 min, décider si ça vaut plus. (2) méthode en diagonale, noter les shapes et la loss: 1h. (3) lecture ligne à ligne avec re-dérivation: réservée aux papiers qui comptent pour TOI.

▾
🤖 En machine learning

Un chercheur « lit » 20 papiers par semaine mais n'en lit vraiment que 2. Les figures + la loss contiennent 80% de l'information. La section related work se lit en dernier (ou jamais).

🛠 Comment t'en servir

Rituel concret: pour chaque papier retenu, écris en 3 phrases À TOI: le problème, l'idée, la preuve. Si tu n'y arrives pas, tu n'as pas compris: retourne à la passe 2. Ton pipeline digest-hub peut automatiser la passe 1.

💻 En code
# ta fiche de lecture:
class PaperNote:
    def __init__(self, title):
        self.title = title
        self.problem = ''  # 1 phrase: quel probleme?
        self.solution = '' # 1 phrase: quelle idee?
        self.result = ''   # 1 phrase: quels chiffres?
        self.vibe = ''     # mon opinion en 3 mots
    def __repr__(self):
        return f'[{self.problem}] → [{self.solution}] → [{self.result}]'
# une note de 3 lignes par papier, rien de plus. le cerveau ne retient pas plus
⚠️ Le piège

La methode des 3 passes n'est pas optionnelle. Passe 1 (5 min): titre, abstract, figures. Passe 2 (1h): sauf les preuves. Passe 3 (3h+): ligne a ligne. 80% des papiers ne meritent pas la passe 3. Savoir jeter un papier est aussi important que savoir le lire.

Décoder la notation d'un papier

Chaque papier redéfinit ses symboles. Méthode: à la première équation, construis ta table des symboles (symbole → sens → shape). Les papiers sérieux ont une section « Notation »: lis-la TOUJOURS en premier.

▾
La formule
$$x \in \mathbb{R}^d,\ \theta \in \Theta,\ \mathcal{D} = \{(x_i, y_i)\}_{i=1}^n$$
🤖 En machine learning

90% des blocages de lecture viennent d'un symbole raté page 2 et réutilisé page 5. La convention dominante: minuscules = vecteurs, majuscules = matrices, calligraphié (𝒟, 𝒩) = ensembles/lois, indices = position.

🛠 Comment t'en servir

Ta checklist niveau 0 est l'outil: devant une équation opaque, identifie chaque symbole un à un (grec ? indice ? décoration ? shape ?). Une équation n'est jamais dure, elle est juste dense: décompresse-la.

💻 En code
# la table de notation du papier en cours:
notepad = {

# a completer a chaque nouveau papier
⚠️ Le piège

Les memes symboles peuvent avoir des sens DIFFERENTS dans des papiers differents. π peut etre 3.14 (geometrie), la politique (RL), ou la probabilite a priori (Bayes). Le contexte est le seul desambigueur. La section 'Notation' est la page la plus importante du papier.

⌘R

Reproduire avant d'innover

Le rite de passage du chercheur: réimplémenter un papier depuis le texte, sans regarder le code officiel, jusqu'à retrouver (à peu près) les chiffres annoncés. C'est là que se forgent les vraies compétences.

▾
🤖 En machine learning

La crise de la reproductibilité est réelle: beaucoup de résultats ne tiennent pas. Savoir reproduire = savoir détecter les détails cachés qui font tout (le learning rate non mentionné, la data augmentation « oubliée »).

🛠 Comment t'en servir

Commence petit: reproduis « Attention is All You Need » sur un mini-dataset (nanoGPT de Karpathy comme correction). Puis un papier récent de TON domaine. Deux reproductions faites sérieusement valent un master.

💻 En code
# le protocole de reproduction:
def reproduce(paper_code_url, dataset, seed=42):
    # etape 1: faire tourner le code officiel SANS modification
    result_official = run(paper_code_url, dataset, seed)
    # etape 2: verifier qu on retrouve les chiffres ±1%
    assert abs(result_official['acc'] - paper_claim['acc']) < 0.01
    # etape 3: NE CHANGER QU UNE chose
    result_modified = run(paper_code_url, dataset, seed, my_change=True)
    return result_official, result_modified
# c est le protocole qui separe le bricolage de la science
⚠️ Le piège

Reproduire est le MEILLEUR investissement de ton temps: tu decouvres les details que le papier omet (version de lib, preprocessing cache, hyperparametre non mentionne, seed magique). Deux reproductions valent un master dans le domaine concerne.

Ablations et baselines

Une ablation = retirer un composant de ta méthode et mesurer la chute: prouve que chaque pièce sert. Une baseline honnête et bien réglée = le point de comparaison sans lequel ton gain ne veut rien dire.

▾
La formule
$$\Delta = \text{score}_{full} - \text{score}_{-composant}$$
🤖 En machine learning

Ce que les reviewers vérifient en premier. Le péché capital du domaine: comparer sa méthode soigneusement tunée à des baselines réglées avec les pieds. Tes tests ORBIT (le LLM n'apporte pas d'edge durable) étaient exactement cette démarche.

🛠 Comment t'en servir

Discipline: une seule variable change à la fois, plusieurs graines aléatoires, moyenne ± écart-type, et le courage de publier l'ablation qui dessert ton histoire. C'est ça, être chercheur.

💻 En code

⚠️ Le piège

Le pire peche du domaine: comparer sa methode finement tunee a des baselines avec les hyperparametres par defaut. Tu ne mesures pas si ton idee est bonne, tu mesures si tu as passe plus de temps a regler ton modele. La seule comparaison juste: TOUS les modeles tunee avec le meme budget.

n=?

Significativité et rigueur statistique

Un gain de 0.4% sur un run unique n'est pas un résultat, c'est du bruit. Il faut: plusieurs graines, des intervalles de confiance, et l'honnêteté de dire quand les barres d'erreur se chevauchent.

▾
La formule
$$\bar x \pm 1.96\,\frac{s}{\sqrt{n}}$$
🤖 En machine learning

Une part embarrassante des « avancées » publiées disparaît avec 5 graines. Les benchmarks LLM ajoutent un piège moderne: la contamination (le test set était dans les données d'entraînement).

🛠 Comment t'en servir

Standard minimal pour tes propres travaux: 3 à 5 graines, moyenne ± écart-type dans chaque tableau. Tu l'as appliqué en falsifiant LVS à 3078σ: la rigueur qui tue une hypothèse vaut celle qui en valide une.

💻 En code
# test statistique entre deux modeles:
from scipy import stats
# 5 seeds pour chaque modele
scores_A = [92.1, 91.8, 92.3, 91.6, 92.0]  # ton modele
scores_B = [91.9, 91.5, 91.7, 91.3, 91.6]  # baseline
t_stat, p_value = stats.ttest_ind(scores_A, scores_B)
print(f'p = {p_value:.4f}')
if p_value < 0.05:
    print('Difference significative')
else:
    print('Pas de difference concluante (barres d erreur qui se chevauchent)')
⚠️ Le piège

3 seeds, ce n'est pas assez: l'intervalle de confiance est enorme. 5 seeds, c'est le minimum acceptable. 10 seeds, c'est bien. Et meme avec p < 0.05, il y a 5% de chance que ta conclusion soit fausse. C'est le probleme de la replication en science.
