L(θ)

La fonction de coût (loss)

UN nombre qui mesure à quel point le modèle se trompe. Tout l'entraînement consiste à le faire baisser. Choisir la loss = définir ce que « bien » veut dire pour ton problème.

▾
La formule
$$L(\theta) = \frac{1}{n}\sum_i \ell(f_\theta(x_i), y_i)$$
🤖 En machine learning

MSE pour la régression, cross-entropy pour la classification, contrastive pour les embeddings, récompense pour le RL. Une loss mal choisie = un modèle qui optimise la mauvaise chose avec brio.

🛠 Comment t'en servir

Devant tout projet, pose d'abord LA question: « quelle est ma loss et reflète-t-elle vraiment mon objectif métier ? » C'est la première cause d'échec des projets ML, avant les modèles.

💻 En code
# la loss est fonction des POIDS, pas des donnees:
for x, y in loader:                   # les donnees sont fixees
    loss = F.mse_loss(model(x), y)
    loss.backward()                    # ∇_θ L(θ; x, y)
    optimizer.step()                   # θ ← θ - α∇L
    optimizer.zero_grad()
# c'est θ qu'on bouge, pas x
⚠️ Le piège

La loss depend des POIDS du modele. Les donnees sont des constantes fixees. C'est le renversement de perspective le plus important du ML: on ne change pas les donnees, on change le modele pour qu'elles deviennent probables.

↓∇

La descente de gradient

L'algorithme d'apprentissage universel: calcule la pente, fais un pas dans le sens de la descente, répète. C'est tout. Chaque réseau de neurones au monde apprend ainsi.

▾
La formule
$$\theta_{t+1} = \theta_t - \alpha \nabla L(\theta_t)$$
🤖 En machine learning

L'unique équation qui entraîne GPT, Stable Diffusion, AlphaFold et ton petit modèle sklearn. Les milliards investis en GPU servent à exécuter cette ligne des milliards de fois.

🛠 Comment t'en servir

Manipule le Lab 03: vois l'effet du learning rate en direct (trop petit = lent, trop grand = divergence). Ancre cette image, elle t'accompagnera dans tous tes débugs d'entraînement.

💻 En code
# la boucle d'entrainement universelle:
for epoch in range(num_epochs):
    for batch in dataloader:
        loss = model(batch)
        loss.backward()       # calcule ∇L sur CE batch
        optimizer.step()       # θ ← θ - α∇L
        optimizer.zero_grad()  # remet les gradients a zero!
# zero_grad est le geste oublie le plus frequemment
⚠️ Le piège

La descente de gradient ne garantit PAS de trouver le minimum global. Elle trouve un minimum LOCAL, qui depend du point de depart et du learning rate. C'est pour ca que la seed compte.

α

Le learning rate

La taille du pas à chaque itération. L'hyperparamètre le plus important de tout le deep learning. Trop grand: on saute par dessus la vallée et on diverge. Trop petit: des semaines pour converger.

▾
La formule
$$\theta \leftarrow \theta - \alpha \nabla L, \quad \alpha \sim 10^{-5} \text{ à } 10^{-2}$$
🤖 En machine learning

Toute recette d'entraînement commence par régler α. Les LLM utilisent des schedules: warmup (montée douce) puis décroissance cosinus. Une loss qui explose en NaN = presque toujours α trop grand.

🛠 Comment t'en servir

Heuristique de terrain: commence à 3e-4 (Adam), puis cherche par puissances de 10. Si la loss oscille: divise α par 10. Si elle descend trop lentement et régulièrement: multiplie par 3.

💻 En code
# essai systematique des learning rates:
lrs = [1e-4, 3e-4, 1e-3, 3e-3]
for lr in lrs:
    model = create_model()
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    train(model, opt, epochs=5)
    print(f'lr={lr}: loss={test(model):.4f}')
# le meilleur lr varie d'un facteur ~3 entre valeurs
⚠️ Le piège

Le learning rate ideal est rarement 0.1, 0.01 ou 0.001. C'est souvent 3e-4 (pour Adam). Le '3' est plus frequent que le '1'. Pourquoi? Mystere empirique, mais ca marche.

SGD

SGD et mini-batch

Calculer le gradient sur TOUT le dataset à chaque pas est trop coûteux. On l'estime sur un petit batch tiré au hasard: gradient bruité mais 1000x plus rapide, et le bruit aide même à s'échapper des mauvais creux.

▾
La formule
$$\nabla L \approx \frac{1}{|B|}\sum_{i \in B} \nabla \ell_i$$
🤖 En machine learning

Le « S » de stochastique = ce tirage aléatoire. Batch size typique: 32 à quelques millions (LLM). Gros batch = gradient précis mais coûteux; petit batch = bruité mais régularisant.

🛠 Comment t'en servir

DataLoader(dataset, batch_size=64, shuffle=True). Le shuffle n'est pas optionnel: sans lui le gradient est biaisé par l'ordre des données et l'entraînement se dégrade.

💻 En code
# l'effet du batch size sur le bruit du gradient:
for batch_size in [1, 32, 1024]:
    loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)
    loss = train_one_epoch(model, loader)
    print(f'batch {batch_size}: {loss:.4f}')
# batch=1: bruit maximal mais pas cher
# batch=1024: gradient precis mais cher et generalise moins bien
⚠️ Le piège

Un mini-batch de 1 donne un gradient tres bruite (chaque exemple tire dans sa direction). Un batch de la taille du dataset donne le gradient exact mais coûte trop cher. Le sweet spot: entre 32 et 256, la ou le GPU est efficace et le bruit regularise.

β

Le momentum

Au lieu de suivre le gradient brut, on accumule une vitesse (moyenne mobile des gradients passés): comme une bille lourde qui lisse les zigzags et traverse les petits creux.

▾
La formule
$$v \leftarrow \beta v + \nabla L, \quad \theta \leftarrow \theta - \alpha v$$
🤖 En machine learning

Accélère massivement la convergence dans les vallées étroites où le gradient pur oscille. β = 0.9 typiquement: la bille se souvient de ~90% de son élan.

🛠 Comment t'en servir

Présent dans quasiment tous les optimiseurs modernes. Image mentale: gradient seul = randonneur prudent qui recalcule à chaque pas; momentum = boule de bowling lancée dans la pente.

💻 En code
# momentum a la main:
velocity = 0
beta = 0.9
for _ in range(steps):
    grad = compute_gradient(params)
    velocity = beta * velocity + grad   # accumulation
    params -= lr * velocity             # mise a jour avec vitesse
# beta = 0.9: memoire d environ 10 pas
# beta = 0.99: memoire d environ 100 pas
⚠️ Le piège

Le momentum transforme la descente de gradient en 'bille qui descend une pente'. Si le gradient change brusquement de direction (fond d'une vallee erroite), la bille continue tout droit et amortit l'oscillation. β=0.9 est le standard presque universel.

Adam

Adam

L'optimiseur par défaut du deep learning: momentum + learning rate adaptatif par paramètre (les poids au gradient historiquement fort avancent doucement, les autres plus vite).

▾
La formule
$$\theta \leftarrow \theta - \alpha\, \frac{\hat m}{\sqrt{\hat v}+\epsilon}$$
🤖 En machine learning

Le choix standard pour transformers, CNN et à peu près tout. AdamW (sa variante avec weight decay corrigé) entraîne la totalité des LLM modernes.

🛠 Comment t'en servir

torch.optim.AdamW(model.parameters(), lr=3e-4). Sauf raison précise, commence toujours par AdamW: il pardonne les réglages approximatifs bien mieux que SGD.

💻 En code
# Adam = momentum + lr adaptatif:
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,           # learning rate de base
    betas=(0.9, 0.999), # momentum et scaling
    eps=1e-8,           # securite anti-division par zero
    weight_decay=0.01   # L2 decouple
)
# 4 hyperparametres, mais seuls lr et weight_decay sont vraiment a tuner
⚠️ Le piège

AdamW corrige un bug historique d'Adam: dans Adam, le weight_decay s'applique AVANT la normalisation adaptative (donc les gros poids sont penalises plus que les petits). AdamW applique le weight_decay APRES, normalement. Toujours utiliser AdamW, pas Adam.

λ‖θ‖

Régularisation L1 / L2

Ajouter à la loss une pénalité sur la taille des poids: le modèle doit expliquer les données SANS poids extravagants. L2 les rétrécit tous (weight decay), L1 en met certains exactement à 0.

▾
La formule
$$L' = L + \lambda\|\theta\|_2^2$$
🤖 En machine learning

L'arme de base anti-overfitting. L1 fait de la sélection de features automatique (Lasso). Le « W » de AdamW = weight decay intégré proprement.

🛠 Comment t'en servir

weight_decay=0.01 dans AdamW. Interprétation bayésienne élégante: L2 = croire a priori que les poids sont petits (prior gaussien). λ se règle par validation.

💻 En code
# l'effet du weight decay:
model = nn.Linear(10, 1)
optimizer = torch.optim.AdamW(model.parameters(), weight_decay=0.1)
# a chaque step, les poids sont multiplies par (1 - lr * wd) ≈ 0.99997
# c'est un 'retrecissement continu' vers zero
# les poids non utiles sont doucement pousses vers 0
⚠️ Le piège

La regularisation L2 (weight decay) n'empeche pas l'overfitting par magie: elle encode une croyance a priori que les poids doivent rester petits. Un poids de 100 est 'surprenant' et doit etre justifie par une forte reduction de la loss.

∪

Convexité et minima locaux

Fonction convexe = un seul creux (un bol): la descente de gradient trouve LE minimum garanti. Les réseaux profonds sont non convexes: des milliards de creux, cols et plateaux.

▾
La formule
$$f(\tfrac{x+y}{2}) \le \tfrac{f(x)+f(y)}{2}$$
🤖 En machine learning

Régression linéaire/logistique: convexes, convergence garantie. Deep learning: non convexe, mais surprise empirique: en très haute dimension, la plupart des minima locaux sont bons et les vrais pièges sont les points-selles.

🛠 Comment t'en servir

Retiens la conséquence pratique: en deep learning, relancer avec une autre graine aléatoire donne un autre minimum, souvent aussi bon. D'où l'usage des moyennes sur plusieurs runs dans les papiers sérieux.

💻 En code
# la fonction de loss d'un MLP:
def loss_mlp(theta, x, y):
    h = F.relu(W1 @ x + b1)  # non-lineaire
    out = W2 @ h + b2
    return F.mse_loss(out, y)
# a cause de ReLU, cette fonction n'est PAS convexe
# il y a plusieurs minima, pas un seul bol
⚠️ Le piège

Les reseaux profonds ne sont PAS convexes: leur paysage de loss a des creux, des bosses, des cols. Le 'bon' minimum n'est pas garanti. Mais en haute dimension, la plupart des minima locaux ont une loss proche du minimum global.

⏹

Early stopping et schedules

Surveiller la loss de validation et arrêter quand elle remonte (le modèle commence à mémoriser). Les schedules font varier α au fil du temps: montée douce (warmup) puis décroissance.

▾
La formule
$$\alpha_t = \alpha_{max}\cdot \tfrac{1}{2}\left(1+\cos\tfrac{\pi t}{T}\right)$$
🤖 En machine learning

L'early stopping est la régularisation gratuite la plus utilisée au monde. Le duo warmup + cosine decay est la recette standard d'entraînement des transformers.

🛠 Comment t'en servir

Garde toujours un set de validation, sauvegarde le meilleur checkpoint (patience=10), et trace TOUJOURS les deux courbes train/val: leur divergence est le battement de cœur de ton entraînement.

💻 En code
# le schedule cosine avec warmup:
optimizer = torch.optim.AdamW(model.parameters(), lr=0)
scheduler = torch.optim.lr_scheduler.CosineAnnealingWarmRestarts(optimizer, T_0=100)
# warmup: lr monte de 0 a 3e-4 sur les premiers steps
# cosine: lr descend en douceur vers 0
# pourquoi? les premiers pas sont critiques: un lr plein casse les poids frais
⚠️ Le piège

L'early stopping est la regularisation la plus utilisee au monde: arrete l'entrainement quand la loss de validation remonte. Pas d'hyperparametre, pas de cout, et ca fonctionne parce que le modele commence par apprendre les vrais motifs avant de memoriser le bruit.
