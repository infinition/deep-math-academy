⊕

Le neurone

L'unité de calcul: produit scalaire poids·entrée + biais, puis une fonction d'activation non linéaire. Tu connais déjà chaque morceau (niveaux 1, 2, 6): un neurone = ax+b passé dans une non-linéarité.

▾
La formule
$$a = \phi(w^\top x + b)$$
🤖 En machine learning

Empilés par milliers, les neurones composent des fonctions arbitrairement complexes (théorème d'approximation universelle). Chaque neurone apprend à détecter UN motif dans son entrée.

🛠 Comment t'en servir

Démystification totale: pas de magie biologique, juste dot product + biais + activation. Écris-en un en NumPy en 3 lignes, c'est le meilleur vaccin contre le jargon.

💻 En code
# un neurone artificiel:
class Neurone(nn.Module):
    def __init__(self, n_entrees):
        super().__init__()
        self.w = nn.Parameter(torch.randn(n_entrees))
        self.b = nn.Parameter(torch.randn(1))
    def forward(self, x):
        z = x @ self.w + self.b  # somme ponderee + biais
        return F.relu(z)          # non-linearite
# un neurone = une machine a detecter un motif dans l entree
⚠️ Le piège

Un neurone SEUL avec ReLU cree une frontiere lineaire dans l'espace: il est 'actif' d'un cote, 'inactif' de l'autre. Empiler des neurones, c'est superposer ces frontieres pour decouper l'espace en regions de plus en plus complexes.

ReLU

Les fonctions d'activation

La non-linéarité insérée entre les couches. Sans elle, empiler 100 couches linéaires = une seule couche linéaire (les matrices se multiplient entre elles). ReLU = max(0, x): brutale, rapide, efficace.

▾
La formule
$$\text{ReLU}(x)=\max(0,x)$$
🤖 En machine learning

ReLU domine les CNN/MLP; GELU (version lissée) équipe les transformers; tanh/sigmoid survivent dans les LSTM. Le choix influence la circulation du gradient (ReLU ne sature pas côté positif).

🛠 Comment t'en servir

Par défaut: ReLU (ou GELU pour un transformer). Symptôme à connaître: des « neurones morts » (toujours à 0) si le learning rate est trop violent; LeakyReLU corrige ça.

💻 En code
# courbes des activations:
import matplotlib.pyplot as plt
x = torch.linspace(-5, 5, 100)
plt.plot(x, F.relu(x), label='ReLU')
plt.plot(x, torch.sigmoid(x), label='Sigmoid')
plt.plot(x, torch.tanh(x), label='Tanh')
# ReLU: 0 pour x < 0, x pour x > 0
# Sigmoid: S doux entre 0 et 1
# Tanh: S entre -1 et 1
# le choix = la forme de la non-linearite
⚠️ Le piège

Les neurones 'morts' de ReLU (toujours a 0) sont un probleme reel: ils ne propagent jamais de gradient et n'apprennent plus. Dans un grand modele avec 10% de neurones morts par couche, apres 10 couches il reste (0.9)^10 ≈ 35% de neurones vivants.

MLP

Couche dense et MLP

Une couche dense = une matrice W (chaque neurone de sortie connecté à toutes les entrées) + activation. Un MLP = plusieurs couches denses empilées: le réseau de neurones de base.

▾
La formule
$$h = \phi(W_2\,\phi(W_1 x + b_1) + b_2)$$
🤖 En machine learning

Le MLP est partout: classifieur final des CNN, bloc feed-forward des transformers (2/3 de leurs paramètres!), tête de projection des modèles contrastifs.

🛠 Comment t'en servir

nn.Sequential(nn.Linear(784,256), nn.ReLU(), nn.Linear(256,10)). Construis et entraîne un MLP sur MNIST de bout en bout: rite de passage obligatoire, une soirée suffit.

💻 En code
# compter les parametres d un MLP:
model = nn.Sequential(
    nn.Linear(784, 256),  # 784*256 + 256 = 200,960 params
    nn.ReLU(),
    nn.Linear(256, 128),  # 256*128 + 128 = 32,896 params
    nn.ReLU(),
    nn.Linear(128, 10)    # 128*10 + 10 = 1,290 params
)
total = sum(p.numel() for p in model.parameters())  # 235,146
# 235k parametres pour un petit reseau
⚠️ Le piège

La premiere couche d'un MLP sur des images 224×224 a 224*224*3 = 150 528 entrees. Une couche dense avec 1000 neurones → 150 MILLIONS de parametres pour UNE couche. C'est pour ca que les CNN existent.

→

Le forward pass

L'inférence: l'entrée traverse les couches une à une jusqu'à la sortie. Chaque couche transforme la représentation, du brut (pixels, tokens) vers l'abstrait (concepts, probabilités).

▾
La formule
$$x \rightarrow h_1 \rightarrow h_2 \rightarrow \dots \rightarrow \hat y$$
🤖 En machine learning

Ce que fait le modèle en production à chaque requête. Les représentations intermédiaires hᵢ (les « activations ») sont réutilisables: c'est la base du transfer learning et des embeddings.

🛠 Comment t'en servir

output = model(x). Pour comprendre un réseau, imprime la shape après chaque couche: suivre la transformation des shapes = suivre le raisonnement du modèle.

💻 En code
# tracer les activations pendant un forward:
activations = {}
def hook_fn(name):
    def hook(module, input, output):
        activations[name] = output.detach()
    return hook
for name, layer in model.named_modules():
    layer.register_forward_hook(hook_fn(name))
output = model(x)
for name, act in activations.items():
    print(f'{name}: {act.shape}, mean={act.mean():.3f}, std={act.std():.3f}')
⚠️ Le piège

Le forward pass MEMORISE toutes les activations intermediaires: c'est le 'graphe de calcul'. C'est pour ca qu'un forward consomme de la memoire GPU proportionnellement a la profondeur du reseau. En inference avec torch.no_grad(), ce graphe n'est pas stocke.

←∇

La backpropagation

L'algorithme qui calcule le gradient de la loss par rapport à CHAQUE poids: la règle de la chaîne (niveau 3) appliquée en remontant de la loss vers l'entrée, en réutilisant les calculs intermédiaires. Efficace: un aller-retour = tous les gradients.

▾
La formule
$$\frac{\partial L}{\partial W_1} = \frac{\partial L}{\partial h_2}\frac{\partial h_2}{\partial h_1}\frac{\partial h_1}{\partial W_1}$$
🤖 En machine learning

L'algorithme qui a rendu le deep learning possible (1986, généralisé 2012+). Chaque loss.backward() de chaque framework exécute exactement ceci via l'autodiff.

🛠 Comment t'en servir

Exercice qui change une carrière: coder backprop à la main sur un réseau 2 couches en NumPy (le cours « micrograd » de Karpathy le fait en 2h). Après ça, plus jamais de boîte noire.

💻 En code
# backprop a la main sur un mini-reseau:
# forward:
h = W1 @ x + b1  # [128] -> [64]
h_relu = max(0, h)  # [64]
y_pred = W2 @ h_relu + b2  # [64] -> [10]
# backward (regle de la chaine):
dL_dy = 2 * (y_pred - y_true) / n  # derivee de MSE
dL_dW2 = dL_dy @ h_relu.T
dL_dh_relu = W2.T @ dL_dy
dL_dh = dL_dh_relu * (h > 0).float()  # derivee de ReLU
dL_dW1 = dL_dh @ x.T
⚠️ Le piège

La backpropagation est la raison pour laquelle le deep learning a conquis le monde. Avant 1986, on ne savait pas entrainer les reseaux multicouches. Le 'c'est juste la regle de la chaine' est vrai mais en cache la prouesse: appliquer cette regle a des millions de parametres automatiquement.

W₀

L'initialisation des poids

On ne démarre ni à zéro (symétrie: tous les neurones apprendraient la même chose) ni au hasard brut (explosion/extinction des signaux). On tire des gaussiennes calibrées selon la taille des couches (Xavier, He).

▾
La formule
$$W \sim \mathcal{N}\!\left(0, \tfrac{2}{n_{in}}\right)$$
🤖 En machine learning

Une mauvaise init = un réseau qui n'apprend rien ou diverge à l'époque 1. Les recettes He (pour ReLU) et Xavier (pour tanh) maintiennent la variance des activations constante de couche en couche.

🛠 Comment t'en servir

PyTorch applique de bonnes init par défaut: sache juste qu'elles existent et pourquoi. Si un réseau custom n'apprend rien, l'init fait partie du top 3 des suspects avec le learning rate et les données.

💻 En code
# tester l initialisation:
model = nn.Sequential(nn.Linear(100, 100), nn.ReLU(), nn.Linear(100, 100))
x = torch.randn(32, 100)
# mesurer la variance des activations couche par couche:
for name, layer in model.named_children():
    x = layer(x)
    print(f'{name}: std={x.std():.3f}')
# si la variance explose (×10 par couche) ou s effondre (÷10): mauvaise init
⚠️ Le piège

L'initialisation de He utilise une variance de 2/n_in (n_in = nombre d'entrees du neurone). Pourquoi 2? Parce que ReLU met a zero la moitie des neurones en moyenne: la variance est deja divisee par 2 a cause de cette mise a zero. Le facteur 2 compense exactement cette perte. Sans ce calibrage, les activations explosent ou s'eteignent de couche en couche.

drop

Le dropout

Pendant l'entraînement, éteindre aléatoirement une fraction p des neurones à chaque batch: le réseau ne peut compter sur aucun neurone en particulier et apprend des représentations redondantes, robustes.

▾
La formule
$$h' = h \odot m, \quad m_i \sim \text{Bernoulli}(1-p)$$
🤖 En machine learning

Régularisation standard des MLP et transformers (p entre 0.1 et 0.5). Interprétation élégante: entraîner un ensemble implicite de milliers de sous-réseaux qui votent.

🛠 Comment t'en servir

nn.Dropout(0.1). Piège classique en production: oublier model.eval(), qui désactive le dropout à l'inférence. Symptôme: des prédictions qui changent à chaque appel identique.

💻 En code
# dropout pendant l'entrainement:
model = nn.Sequential(
    nn.Linear(784, 256),
    nn.Dropout(0.5),  # 50% des neurones eteints
    nn.ReLU(),
    nn.Linear(256, 10)
)
model.train()  # mode entrainement: dropout ACTIF
for batch in loader:
    out = model(batch)  # a chaque batch, un masque different

model.eval()   # mode evaluation: dropout DESACTIVE
out = model(batch)  # tous les neurones sont presents
⚠️ Le piège

En entrainement, dropout eteint une fraction p des neurones et MULTIPLIE les sorties par 1/(1-p) pour que l'amplitude moyenne reste la meme (c'est 'l'inverted dropout', la version standard depuis 2014). Sans cette compensation, l'intensite des signaux chuterait entre train et eval. Et SURTOUT: sans model.eval(), le dropout reste actif en production et les predictions changent a chaque appel.

BN

Batch normalization

Standardiser les activations (moyenne 0, variance 1) au sein de chaque batch, puis laisser le réseau réapprendre échelle et décalage. Stabilise et accélère énormément l'entraînement.

▾
La formule
$$\hat h = \frac{h - \mu_B}{\sqrt{\sigma_B^2+\epsilon}}\cdot\gamma + \beta$$
🤖 En machine learning

Incontournable dans les CNN (ResNet). Les transformers utilisent sa cousine layer norm (niveau 8) car la normalisation par batch se marie mal avec les séquences de longueurs variables.

🛠 Comment t'en servir

nn.BatchNorm2d(channels) après la convolution, avant l'activation. Même piège que le dropout: comportement différent en train et en eval, d'où l'importance rituelle de model.eval().

💻 En code
# BatchNorm en action:
class MyBlock(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(256, 256)
        self.bn = nn.BatchNorm1d(256)
    def forward(self, x):
        return F.relu(self.bn(self.linear(x)))
# la norm calcule mu et sigma sur le BATCH courant
# en eval, les mu/sigma accumules pendant l entrainement sont utilises
⚠️ Le piège

BatchNorm normalise PAR BATCH. Si ton batch est de taille 1 (ex: streaming), la moyenne = la valeur elle-meme → variance nulle → c'est la catastrophe. Solution: utiliser LayerNorm (normalise par echantillon) ou GroupNorm. C'est pourquoi les LLM utilisent LayerNorm.

⊞

La convolution (CNN)

Faire glisser un petit filtre (3×3 par ex.) sur l'image: mêmes poids partout, chaque position produit une réponse « ce motif est-il ici ? ». Exploite le fait qu'un chat en haut à gauche reste un chat en bas à droite.

▾
La formule
$$(I * K)_{ij} = \sum_{m,n} I_{i+m,j+n} K_{mn}$$
🤖 En machine learning

Vision par ordinateur: classification, détection, segmentation, imagerie médicale. Les premières couches apprennent des bords, puis des textures, puis des objets: hiérarchie visuelle émergente.

🛠 Comment t'en servir

nn.Conv2d(3, 64, kernel_size=3, padding=1). Le partage de poids divise les paramètres par des ordres de grandeur vs une couche dense: c'est ça, le génie du CNN.

💻 En code
# convolution 1D intuitive:
signal = torch.tensor([1, 3, 2, 5, 1, 4])
filtre = torch.tensor([-1, 0, 1])  # detecteur de pente
# le filtre glisse sur le signal:
# position 1: (-1*1 + 0*3 + 1*2) = 1 (montee)
# position 2: (-1*3 + 0*2 + 1*5) = 2 (montee rapide)
# position 3: (-1*2 + 0*5 + 1*1) = -1 (descente)
# resultat: [1, 2, -1] = pentes locales
⚠️ Le piège

Un filtre de convolution a une PROPRIETE FONDAMENTALE: il est invariant par translation. Detecter un bord en haut a gauche de l'image utilise le MEME filtre qu'en bas a droite. 9 poids appris, et le motif est detecte partout. C'est le genie du CNN.

h_t

RNN et LSTM

Traiter une séquence pas à pas en maintenant un état mémoire h_t mis à jour à chaque élément. Le LSTM ajoute des portes (oublier/écrire/lire) pour retenir l'information sur de longues distances.

▾
La formule
$$h_t = \phi(W_h h_{t-1} + W_x x_t)$$
🤖 En machine learning

Ex-rois du texte et des séries temporelles, largement détrônés par les transformers (parallélisables, meilleure longue portée). Survivent en embarqué, streaming temps réel, et inspirent les SSM modernes (Mamba).

🛠 Comment t'en servir

À connaître pour lire la littérature pré-2018 et comprendre POURQUOI l'attention a gagné: le RNN traite t=1000 après les 999 précédents; le transformer traite tout en parallèle.

💻 En code
# LSTM: memoriser sur de longues distances
lstm = nn.LSTM(768, 256, num_layers=2, batch_first=True)
# entrees: x de shape (batch, sequence, 768)
# sortie: output (batch, sequence, 256)
# etat cache: h_n (2, batch, 256)
# etat cellule: c_n (2, batch, 256) - LA MEMOIRE LONGUE
output, (h_n, c_n) = lstm(x)
# le LSTM a 4 portes (oublier, entree, sortie, candidat) pour controler ce qui entre et sort de la memoire
⚠️ Le piège

L'avantage du LSTM sur le RNN simple: le gradient peut traverser la 'cellule' sans etre multiplie par des poids, donc il ne s'evanouit pas sur les longues sequences. L'inconvenient: il reste SEQUENTIEL, chaque token attend le precedent.

emb

Les embeddings

Représenter un objet discret (mot, token, utilisateur, produit) par un vecteur dense appris, tel que la géométrie reflète le sens: les voisins dans l'espace sont proches dans le monde.

▾
La formule
$$e = E[i] \in \mathbb{R}^d$$
🤖 En machine learning

Première couche de tout LLM (token → vecteur). Recherche sémantique, RAG, recommandation, célèbre arithmétique roi - homme + femme ≈ reine. L'idée la plus féconde du NLP moderne.

🛠 Comment t'en servir

nn.Embedding(vocab_size, 768) ou une API d'embeddings pour du RAG. Compétence directement monétisable: similarité cosinus sur embeddings = moteur de recherche sémantique en 20 lignes.

💻 En code
# les embeddings apprennent la semantique:
embedding = nn.Embedding(vocab_size=10000, embedding_dim=768)
# au debut, les vecteurs sont aleatoires, sans signification
word_idx = torch.tensor([42, 128, 7])  # indices de mots
vectors = embedding(word_idx)            # [3, 768]
# apres entrainement, les vecteurs de mots similaires sont proches
# roi - homme + femme ≈ reine
similarite = F.cosine_similarity(emb_roi - emb_homme + emb_femme, emb_reine, dim=0)
⚠️ Le piège

L'embedding n'est PAS un dictionnaire: il n'y a pas de 'sens' stocke explicitement. C'est un espace vectoriel ou les relations sont GEOMETRIQUES. 'Roi' est proche de 'reine' dans la meme direction que 'homme' est proche de 'femme'. L'arithmetique vectorielle du sens.
