lim

La limite

« Vers quoi tend f(x) quand x s'approche d'une valeur ? » On n'atteint jamais le point, on regarde le comportement à l'approche. C'est la fondation qui définit la dérivée.

▾
La formule
$$\lim_{h \to 0} \frac{f(x+h)-f(x)}{h}$$
🤖 En machine learning

Concept d'arrière-plan: il justifie les dérivées et donc tout l'apprentissage. Apparaît aussi dans les analyses asymptotiques (que se passe-t-il quand n → ∞ ?).

🛠 Comment t'en servir

Pas besoin de virtuosité calculatoire: comprends l'idée de « zoom infini » et passe vite à la dérivée, qui est la vraie star.

💻 En code
# verification numerique de gradient:
def grad_check(f, x, eps=1e-6):
    return [(f(x + eps) - f(x - eps)) / (2*eps)]
# compare avec autograd pour debugger
⚠️ Le piège

La limite est une idee therorique geniale qui devient un calcul numerique des que tu la concretises avec un petit h. Trop petit: stabilite numerique. Trop grand: approximation grossiere. h = 1e-6 est le compromis standard.

f′(x)

La dérivée

La dérivée = la pente de la courbe en un point = de combien bouge la sortie si je pousse l'entrée d'un chouïa. Positive: ça monte. Négative: ça descend. Nulle: sommet ou creux.

▾
La formule
$$f'(x) = \lim_{h\to 0}\frac{f(x+h)-f(x)}{h}$$
🤖 En machine learning

C'est le concept central de TOUT l'apprentissage: la dérivée de la loss par rapport à un poids dit si augmenter ce poids augmente ou diminue l'erreur. On bouge alors dans le sens opposé.

🛠 Comment t'en servir

Vois la dérivée comme une sensibilité: dL/dw = -3 signifie « augmenter w de 0.01 baisse la loss d'environ 0.03 ». Le Lab 01 t'affiche la tangente en direct: joue avec.

💻 En code
# petite astuce: la derivee de ReLU en 0
# normalement elle n'existe pas (angle droit)
# PyTorch dit que c'est 0 par convention
# ca n'a quasiment jamais d'impact en pratique
x = torch.tensor(0.0, requires_grad=True)
y = torch.relu(x)
y.backward()
print(x.grad)  # 0.0 (convention PyTorch)
⚠️ Le piège

La derivee de ReLU en 0 n'existe pas mathematiquement (c'est un angle). Mais on a besoin d'une valeur pour la backprop. Les frameworks (PyTorch, TensorFlow) ont choisi 0 par convention, et ca marche parce que la probabilit'e de tomber exactement sur 0 pendant l'entrainement est infime.

∂f/∂x

La dérivée partielle

Pour une fonction à plusieurs entrées: la dérivée par rapport à UNE variable, en gelant toutes les autres. Le symbole ∂ (« d rond ») signale qu'il y a d'autres variables en pause.

▾
La formule
$$\frac{\partial f}{\partial x} \Big|_{y \text{ fixé}}$$
🤖 En machine learning

Un modèle a des milliards de poids: pour chacun on calcule ∂L/∂wᵢ, sa responsabilité individuelle dans l'erreur, les autres poids étant figés.

🛠 Comment t'en servir

Mentalement: « toutes choses égales par ailleurs ». Calculer ∂/∂x revient à dériver normalement en traitant y, z... comme des constantes.

💻 En code
f = lambda x, y: x**2 * y
# derivee partielle par rapport a x: 2*x*y
# derivee partielle par rapport a y: x**2
# en un point (3, 2): d/dx = 12, d/dy = 9
⚠️ Le piège

En backprop, le gradient de la loss par rapport a chaque poids est une derivee partielle. Les autres poids sont 'geles' le temps de cette derivee. Les milliards de ∂ forment le vecteur ∇.

∇f

Le gradient

Toutes les dérivées partielles rangées dans un vecteur. Propriété magique: ∇f pointe dans la direction de plus forte montée. Donc -∇f = la direction de plus forte descente.

▾
La formule
$$\nabla f = \left[\frac{\partial f}{\partial x_1},\dots,\frac{\partial f}{\partial x_n}\right]$$
🤖 En machine learning

La règle d'apprentissage universelle: θ ← θ - α∇L. Chaque étape d'entraînement de chaque réseau au monde applique cette ligne. « Gradient » est LE mot du deep learning.

🛠 Comment t'en servir

loss.backward() calcule ∇L, optimizer.step() fait le pas. Image mentale: tu es dans le brouillard sur une montagne, le gradient est la pente sous tes pieds, tu descends.

💻 En code
# visualiser le gradient comme une fleche:
x = torch.linspace(-3, 3, 100)
L = x**2
grad = 2*x  # dL/dx
# grad positif: L monte quand x monte
# grad negatif: L descend quand x monte
# le minimum est la ou grad change de signe
⚠️ Le piège

∇L pointe vers la direction de PLUS FORTE MONTEE. Pour minimiser, on prend -∇L. Si ta loss augmente pendant l'entrainement, c'est que ton learning rate est trop grand et que tu 'depasse' la vallee a chaque pas.

chain

La règle de la chaîne

Pour dériver une composition f(g(x)): on multiplie les dérivées des étages. La sensibilité totale = produit des sensibilités locales le long du chemin.

▾
La formule
$$\frac{d}{dx}f(g(x)) = f'(g(x)) \cdot g'(x)$$
🤖 En machine learning

La backpropagation N'EST RIEN D'AUTRE que la règle de la chaîne appliquée couche par couche, de la loss vers l'entrée. Comprendre cette carte = comprendre comment les réseaux apprennent.

🛠 Comment t'en servir

Vois chaque couche comme un engrenage: la dérivée finale = produit des rapports de chaque engrenage. Le vanishing gradient s'explique ici: multiplier plein de nombres < 1 tend vers 0.

💻 En code
# la backprop, c'est la regle de la chaine appliquee:
def forward(self, x):
    h = F.relu(self.fc1(x))
    out = self.fc2(h)
    return out
# dL/dW1 = dL/dout * dout/dh * dh/dW1
# les gradients des couches profondes (2) sont REUTILISES pour les couches peu profondes (1)
⚠️ Le piège

Le vanishing gradient: si chaque maillon de la chaine a une derivee < 1 (ex: sigmoide ≈ 0.25 max), le produit de 50 maillons ≈ 0.25^50 ≈ 10^{-30} → gradient mort. C'est pourquoi les connexions residuelles (x + f(x)) ont ete inventees.

J

La Jacobienne

Quand la fonction sort un VECTEUR (pas un seul nombre): la Jacobienne est la matrice de toutes les dérivées de chaque sortie par rapport à chaque entrée. C'est la généralisation matricielle de f′.

▾
La formule
$$J_{ij} = \frac{\partial f_i}{\partial x_j}$$
🤖 En machine learning

Backprop propage en réalité des produits de Jacobiennes de couche en couche. Utilisée aussi en robotique (bras articulés) et dans les normalizing flows.

🛠 Comment t'en servir

Lecture suffisante: « Jacobienne = tableau des sensibilités de chaque sortie à chaque entrée ». Les frameworks la calculent pour toi via l'autodiff.

💻 En code
def f(x):  # R^2 -> R^3
    return torch.stack([x[0] + x[1], x[0]**2, x[1]**2])
x = torch.tensor([1., 2.])
J = torch.autograd.functional.jacobian(f, x)
print(J.shape)  # (3, 2): 3 sorties, 2 entrees
⚠️ Le piège

La Jacobienne est une matrice de toutes les derivees partielles. Pour un reseau de neurones, c'est le gradient de chaque sortie par rapport a chaque entree. Mais on ne la calcule JAMAIS entierement: trop grosse (N_sorties x N_entrees).

H

La Hessienne

La matrice des dérivées secondes: la courbure. Elle dit si tu es dans une vallée (bol), sur une crête, ou sur un col (selle). La dérivée donne la pente, la Hessienne donne la forme du terrain.

▾
La formule
$$H_{ij} = \frac{\partial^2 L}{\partial \theta_i \partial \theta_j}$$
🤖 En machine learning

Explique pourquoi certains entraînements zigzaguent (vallées étroites). Les optimiseurs de second ordre (Newton, L-BFGS, K-FAC) l'exploitent. La « sharpness » des minima (liée à la généralisation) se lit dans H.

🛠 Comment t'en servir

Trop grosse pour être calculée sur un vrai réseau (milliards²): on l'approxime ou on l'ignore. Retiens le concept de courbure, il éclaire tous les débats sur les optimiseurs.

💻 En code
def loss(theta):
    return theta[0]**2 + theta[1]**3
x = torch.tensor([2., 1.], requires_grad=True)
H = torch.autograd.functional.hessian(loss, x)
print(H)  # [[2, 0], [0, 6*theta[1]]] = [[2, 0], [0, 6]]
⚠️ Le piège

La Hessienne n'est pas calculee sur les vrais modeles (O(n^2) memoire pour n milliards de poids). Mais le concept de 'courbure' explique pourquoi Adam marche mieux que SGD: il adapte le pas a la courbure de chaque direction.

∫

L'intégrale

L'opération inverse de la dérivée: l'aire sous la courbe = accumuler des contributions infinitésimales. C'est un Σ continu.

▾
La formule
$$\mathbb{E}[X] = \int x\, p(x)\, dx$$
🤖 En machine learning

En probas continues, l'espérance est une intégrale. Les modèles de diffusion et les VAE intègrent sur du bruit. En pratique ML: on approxime presque toujours l'intégrale par une moyenne d'échantillons (Monte Carlo).

🛠 Comment t'en servir

Réflexe pragmatique: intégrale illisible dans un papier → cherche la phrase « we approximate by sampling ». ∫ ≈ samples.mean(). Tu viens de comprendre la moitié des maths des modèles génératifs.

💻 En code
# Monte Carlo: integral approx par echantillonnage
samples = torch.randn(10000)  # tires de N(0,1)
estimate = (samples**2).mean()   # approx de ∫ x^2 N(0,1) dx = 1
print(estimate)  # ≈ 0.99, pas exactement 1
⚠️ Le piège

Toute integrale en ML est approximee par Monte Carlo: on echantillonne et on moyenne. L'erreur d'approximation decroit en 1/√n. Pour gagner une decimale de precision, il faut 100× plus d'echantillons.
